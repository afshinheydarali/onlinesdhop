# برنامه اجرایی

## معماری حداقلی

- Python 3.12 و aiogram 3.31 برای polling و FSM حافظه‌ای؛ SQLite برای داده‌های پایدار.
- `config.py` برای environment، `validation.py` برای ورودی و caption، `database.py` برای تراکنش‌ها، و `bot.py` برای handler و انتشار.
- نگهداری `file_id` تلگرام به‌جای دانلود عکس و استفاده از HTML escape‌شده برای متن کانال.

## مدل داده

- `admins`: شناسه تلگرام یکتا، کد ادمین یکتا، نام، وضعیت فعال و زمان ایجاد.
- `orders`: شناسه عمومی یکتا، ادمین، داده خام نمایشی، تلفن و محصول normalize‌شده، `file_id`، ارتباط `duplicate_of`، token یکتای draft و وضعیت/خطای ارسال.
- ایندکس ترکیبی تلفن/محصول/زمان برای تشخیص سریع سفارش تکراری.

## جریان گفتگو و دسترسی

1. هر پیام و callback در چت خصوصی دوباره با دیتابیس احراز هویت می‌شود؛ owner فقط به مدیریت ادمین‌ها دسترسی ویژه دارد.
2. سفارش مرحله‌ای با دکمه‌های بازگشت، شروع مجدد و لغو جمع‌آوری می‌شود. عکس دارای caption معتبر می‌تواند کل فرم را یکجا تکمیل کند.
3. پیش‌نمایش عکس و اطلاعات، و سپس تأیید/ویرایش/لغو نمایش داده می‌شود.
4. مدیر با `/admin_add`، `/admin_enable`، `/admin_disable` و `/admins` ادمین‌ها را مدیریت می‌کند.

## تکراری و هم‌زمانی

- ارقام فارسی/عربی تبدیل و تلفن‌های `09`، `989` و `+989` به `989...` یکسان می‌شوند؛ محصول trim، فاصله‌ها یکسان و casefold می‌شود.
- تطابق تلفن+محصول در بازه قابل‌تنظیم هشدار بی‌نام می‌دهد و ثبت فقط بعد از تأیید دوم انجام می‌شود.
- بررسی نهایی و درج در `BEGIN IMMEDIATE` انجام می‌شود. token یکتای draft مانع ثبت دوباره ناشی از چندبار کلیک می‌شود.
- انتشار با claim اتمیک، وضعیت‌های `pending/sending/sent/failed` و retry همان رکورد انجام می‌شود؛ شکست هرگز سفارش را حذف نمی‌کند.

## تست، Git و استقرار

- تست‌های `unittest` برای دسترسی، مدیریت ادمین، validation/caption، تراکنش تکراری و idempotency، قالب امن پیام، محدودیت caption و شکست/retry انتشار.
- Git روی branch `feature/telegram-order-bot` با commitهای اتمیک؛ push بعد از هر مرحله فقط در صورت وجود remote و دسترسی.
- اجرای محلی با virtualenv و اجرای production تک‌نمونه‌ای با Docker Compose و volume پایدار SQLite.

## ریسک‌ها و فرضیات

- FSM حافظه‌ای پس از restart پاک می‌شود، اما سفارش تأییدشده در SQLite باقی می‌ماند؛ برای استقرار تک‌نمونه‌ای خواسته‌شده مناسب است.
- Bot API نمی‌تواند همه اعضای پنهان کانال را فهرست کند؛ برنامه نوع کانال و ادمین‌های آن را بررسی می‌کند و خصوصی‌بودن/نبود اعضای اضافی باید هنگام ساخت کانال رعایت شود.
- بین موفقیت شبکه‌ای ارسال تلگرام و ثبت `sent` یک بازه مبهم اجتناب‌ناپذیر وجود دارد؛ retry هم‌زمان ایمن است ولی پس از قطع ناگهانی پردازش ممکن است بررسی دستی کانال لازم باشد.
